## Accepted version policy

Each accepted version must be immutable, reference its parent champion, include code/config/data fingerprints, target and feature definitions, chronological training/validation/research-test periods, a predeclared sealed-holdout policy, leakage audit, walk-forward and robustness results, calibration/error analysis, practical utility/backtest assessment, resource costs, reproduction command, and a signed-off decision rationale. Candidate IDs (`exp-...`) are not release versions. Failed, rejected, and blocked attempts remain in the experiment journal and do not increment the version number.

The supervisor has not created any release tag, accepted model version, or champion manifest.
