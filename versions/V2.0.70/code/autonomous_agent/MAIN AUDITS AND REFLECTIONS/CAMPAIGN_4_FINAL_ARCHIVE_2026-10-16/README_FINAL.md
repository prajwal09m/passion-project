### Audit finding — v1.1.0 per-member measurement path never wired (owner review recommended)

**Finding.** The frozen family definitions require, per poolable
experiment, per-cell / per-rung refutation measurements (regime: 2 cells
`above_sma200`/`below_sma200`; horizon: 3 rungs 1/2/3 sessions; purge: 3
rungs +0/+5/+10; complexity: 1 primary). The v1.1.0 evaluators that judge
these (`recipe_harness.evaluate_regime_cells` / `evaluate_horizon_rungs` /
`evaluate_purge_rungs`) **exist in the codebase but were never invoked by
the production experiment path** — their only callers are the unit tests.
The executed study pipeline is v1.0.0 and emits **pooled metrics only**
(verified 2026-10-16 against all 12 retained poolable workspaces'
`evaluation.json`, all 32 C4 ledger adjudication rows, and the loop's
memory files: zero per-member deltas, CIs, or week-level contributions
exist anywhere; the only `above_sma` strings are the feature name
`spy_above_sma200`).

**Consequences.**
1. No member ever had an unadjusted p-value, so no Holm decision could be
   computed; every predeclared member is `unavailable` at p = 1.0 by the
   owner-frozen C-2 Option A rule, yielding **zero formal refutations** —
   identical to the plan's fail-safe default ("if the pass can never run,
   every provisional signal defaults to INCONCLUSIVE").
2. **The 26 promotions rest on the pooled v1.0.0 decision criteria, not on
   the frozen per-cell IUT ladders.** Both REFUTED and INCONCLUSIVE fail
   the evaluation gate, so no promotion outcome changes retroactively
   (selection integrity is unaffected by design), but the per-cell
   robustness *claims* the ladders were meant to discipline were never
   separately measured.

**Recommendation (owner decision).** Before any future campaign that relies
on the Holm families, wire the v1.1.0 per-cell measurement path into the
production experiment adapter, add an end-to-end acceptance test that a
real (or faithfully re-staged) poolable experiment emits per-member
delta/CI/week-level `g`, and consider a pre-launch freeze check that the
compiled spec's primitive is actually exercised by the executed pipeline.
Nothing here invalidates the campaign's pooled results, the champion chain,
or the sealed holdout.
