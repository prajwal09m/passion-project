**What the campaign did:** an autonomous (non-LLM, outcome-blind, human-approval-free) research
loop that proposed demand-zone ML experiment variations, validated them through five gates
(unit / data integrity / walk-forward / leakage / robustness), executed them against a
frozen reconstructed baseline, and promoted gate-passing improvements to the champion chain.
It ran uninterrupted from Oct 5 evening until Oct 8 night, when the proposal backlog was
exhausted (`created 0` for every generate phase from Oct 7 onward) and the portfolio
minimums were met, so the loop stopped itself with executions still unspent (38 < 40).

## 8. Known limitations and unresolved items

- `loop_state.json` has **no pre-existing hash record**; its hash is established for the
  first time by this archive's `SHA256SUMS.txt` (and the copy was verified against the
  live file).
- Untagged lifecycle rows in the ledger cannot be attributed to a campaign by tag alone;
  §2 attributes them by timestamp relative to the C3 start (2026-10-05T20:38:45Z) and by
  the C3-tagged execution rows. This is an original-data limitation, not a filtering choice.
- `adapter_events.jsonl`, `stage5_production_run.log`, the 27 `versions/` trees, and all
  other candidate workspaces were deliberately **not** copied (bulk/redundant per archive
  policy); they remain at their original paths and are referenced above where relevant.
- No trading-profitability claims are made or implied; no backtest was run
  (`backtest.status: NOT_RUN`).
- py-spy was installed on the machine during the run's incident diagnosis; it is a
  system-level tool, unrelated to campaign records, and not part of this archive.
